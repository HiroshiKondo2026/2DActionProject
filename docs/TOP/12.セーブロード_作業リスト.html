セーブ/ロード 作業リスト

Phase D（セーブ/ロード）の実装タスク。上から順に進めるのが安全（土台 → 機能 → UI連携）。
凡例： 💻=コード実装（担当:AI） / 🎮=Unity側作業（担当:あなた） / ✅=完了チェック

確定した仕様（前提）

  • セーブ内容：進行状況のみ（現在HP / 最大HP / シーン名 / 所持品 / 装備 / 撃破済みEnemyID / timestamp）。CSV調整値は保存しない
  • スロット：2つ（オートセーブ用 / 通常セーブ用）
  • LoadGame：オート/通常を選ばせる（LoadGame → スロット選択 → ロード実行）
  • オートセーブ発火：AutoSaveOnEnter を置いたシーンの入場時のみ（Stage*-1系・Title・GameOverには置かない）
  • ロード粒度：シーン境界（頭からロード ＋ 保存HP/所持品で開始）
  • Enemy永続化：撃破済みEnemyはロード時に復活させない。生き残りだけフルHPで再配置（farming防止）

STEP 1. 土台（データとファイルI/O）

  • 💻 1-1. SaveData 構造体を作る（JSON化用：hp / maxHp / sceneName / items[{id,count}] / equippedId / defeatedEnemyIds[] / timestamp）
  • 💻 1-2. SaveSystem を作る（persistentDataPath への JSON 読み書き、スロット別、存在判定、timestamp取得）
  • 💻 1-3. PlayerHealth に「現在HP / 最大HP」取得の口を追加（生きた値でセーブするため）
  • 💻 1-4. InventoryManager に「現在の所持品 / 装備」取得の口を確認・整備（既存で足りるか確認）
  • ✅ 1-5. 動作確認：デバッグから SaveSystem.Save → persistentDataPath に JSON が出力されるか

STEP 2. セーブ処理（データ収集 → 書き出し）

  • 💻 2-1. SaveManager（または既存Managerに機能追加）で「現在の生きた状態を集めて SaveData を作る」処理
  • 💻 2-2. オート/通常の2スロットへの Save メソッド
  • 💻 2-3. AutoSaveOnEnter コンポーネント（シーン入場時にオートスロットへ Save）
  • 🎮 2-4. セーブ点シーンに AutoSaveOnEnter を配置（Stage1_2 / Stage1_3 / イベントシーン等。Stage*-1・Title・GameOverには置かない）
  • ✅ 2-5. 動作確認：セーブ点シーンに入る → オートスロットの JSON が更新される

STEP 2.5. Enemy撃破の永続化（farming防止）

  • 💻 2.5-1. SaveableEnemy コンポーネント（個体GUID。OnValidateで空なら自動生成し、シーン配置ごとに一意化）
  • 💻 2.5-2. 撃破トラッカー：Enemy撃破時に、そのGUIDを「現在シーンの撃破済みセット」へ記録
  • 💻 2.5-3. セーブ時：撃破済みセットを SaveData.defeatedEnemyIds に収集
  • 💻 2.5-4. ロード時：シーン読み込み後、撃破済みIDのEnemyを消す（生き残りはフルHPのまま）
  • 🎮 2.5-5. 各Enemyプレハブに SaveableEnemy を付与（シーン配置インスタンスごとにGUIDが振られるか確認）
  • ✅ 2.5-6. 動作確認：敵を倒す → 手動セーブ → ロード → 倒した敵は復活せず、生き残りはフルHP。ドロップ増殖ができないこと

STEP 3. ロード処理（読み出し → 復元 → 遷移）

  • 💻 3-1. FadeController に FadeOut（透明→黒）を追加、またはロード用の遷移メソッドを用意
  • 💻 3-2. ロード処理：SaveData 読み出し → GameData へ流し込み → FadeOut → シーンロード → FadeIn
  • 💻 3-3. ロード時、所持品は ItemAssetDatabase で id→ItemData に解決して復元
  • ✅ 3-4. 動作確認：デバッグからロード実行 → 保存シーンが頭から始まり、HP/所持品が復元される

STEP 4. タイトル画面のUI（NewGame / LoadGame）

  • 🎮 4-1. Title に NewGame / LoadGame の縦並び選択UI（Text ＋ 選択マーカー）を配置
  • 🎮 4-2. LoadGame後の「オート / 通常」スロット選択UIを配置
  • 💻 4-3. TitleManager（または新規）に選択UI制御：上下キー切替 → 決定 → startSE → ロード実行
  • 💻 4-4. NewGame：GameData.ResetData() → 通常開始（既存フロー流用）
  • 🎮 4-5. セーブが存在しないときの LoadGame の扱い（非活性/非表示）を決めて反映
  • ✅ 4-6. 動作確認：Title → LoadGame → スロット選択 → 保存地点から再開

STEP 5. メニュー画面のUI（Save / Load）

  • 🎮 5-1. Menu に Save / Load のUI項目を追加
  • 💻 5-2. InventoryMenuUI の MenuState に Save/Load 用の状態を追加
  • 💻 5-3. Save：決定 → 既存 ConfirmationPopupUI（はい/いいえ）→ はいで通常スロットへ上書き
  • 💻 5-4. Load：決定 → オート/通常スロット選択 → ロード実行（STEP3の遷移を呼ぶ）
  • 🎮 5-5. 確認ポップアップ（はい/いいえ）を Save/Menu から参照できるよう配線
  • ✅ 5-6. 動作確認：メニューから Save → 通常スロット更新 / メニューから Load → 再開

STEP 6. 仕上げ・例外対応

  • 💻 6-1. セーブファイルが壊れている/バージョン不一致のときの安全処理（読めなければ NewGame 相当に倒す）
  • 💻 6-2. 解決できない itemId（アイテム削除等）がセーブにある場合のフォールバック（その項目をスキップ＋警告）
  • 🎮 6-3. GameData が Title 起動直後に存在するか確認（無ければ SaveSystem 単独で成立する設計になっているか確認）
  • ✅ 6-4. 通し確認：NewGame → 進行 → オートセーブ → 手動セーブ → タイトル/メニューからロード → 復元
  • 📄 6-5. セーブ/ロード仕様書（md）を出力

メモ・懸念（進行中に埋めていく）

  • LoadGame のスロット選択UIは Title と Menu で共通化できると管理が楽
  • 「初めて入ったときの状態」＝敵状態・座標は保存しない（シーンを頭からロード）方針
  • timestamp は表示にも使える（「オート: 12:34 / 通常: 昨日」等）が、まずは内部比較用でよい
