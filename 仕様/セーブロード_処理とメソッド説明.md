## STEP 1：土台（データとファイルI/O）

### SaveData.cs

セーブ1件分のデータ。`JsonUtility` でJSON化できるよう、`[Serializable]` の素なクラスにしている。

| フィールド | 型 | 内容 |
| --- | --- | --- |
| `version` | int | フォーマット互換判定用（将来変更時に使う） |
| `savedAtTicks` | long | 保存時刻（UTCのTicks）。スロットの新旧比較・表示用 |
| `currentHP` / `maxHP` | int | 現在HP / 最大HP |
| `sceneName` | string | ロード時に頭から開始するシーン |
| `equippedId` | string | 装備中アイテムのID（未装備は空） |
| `items` | `SavedItem[]` | 所持アイテム（ID＋個数の配列） |
| `defeatedEnemyIds` | `string[]` | このシーンで撃破済みのEnemyのID（ロード時に復活させない） |

- **なぜIDで持つか**：`ItemData`（アセット参照）はJSONに直接書けないため、`id`＋`count`で保存し、ロード時に `ItemAssetDatabase` でID→ItemDataへ解決する。
- **保存するのは進行状況のみ**：player.csv等の調整値は保存しない（起動ごとにCSVから読む方針）。

`SavedItem` … 所持アイテム1件分（`id` / `count`）。

### SaveSystem.cs（static）

セーブデータのディスク読み書き。保存先は `Application.persistentDataPath`。
**どんな失敗でもゲームを落とさず**、ログを出して null / false を返す。

| メソッド | 役割 |
| --- | --- |
| `Save(slot, data)` | 指定スロットへJSON書き出し。`savedAtTicks` に現在時刻を入れてから保存。失敗はLogErrorのみ |
| `Load(slot)` | 指定スロットを読み込み。ファイルが無ければ null（正常系）。壊れていてもLogError＋null |
| `Exists(slot)` | そのスロットのセーブが存在するか。UIの活性/非活性判定に使う |
| `Delete(slot)` | そのスロットのセーブを削除 |
| `FilePath(slot)`（内部） | スロット→ファイルパス（`save_auto.json` / `save_manual.json`） |

`SaveSlot` … `Auto`（オートセーブ用）/ `Manual`（通常セーブ用）の2スロット。

### PlayerHealth.cs（追記）

セーブ時に「生きた現在値」を取るための公開プロパティを追加。
（`GameData` はシーン破棄時にしか更新されないため、手動セーブ時は生きた値が要る）

| メンバ | 役割 |
| --- | --- |
| `CurrentHP` | 現在HPを外部へ公開 |
| `MaxHP` | 最大HPを外部へ公開 |

### InventoryManager.cs（変更なし）

既存の以下がそのまま使えるため追加なし。

| メンバ | 役割 |
| --- | --- |
| `Inventory` | 現在の所持アイテムリスト（`InventoryItem` = itemData＋count） |
| `EquippedItem` | 現在の装備アイテム（`ItemData`） |

### SaveSystemDebug.cs（動作確認用・後で削除可）

Inspectorでコンポーネントを右クリックして動作確認するための開発ツール。

| メニュー | 動作 |
| --- | --- |
| ① 保存先パスをログ表示 | `persistentDataPath` をログに出す |
| ② テスト用データを書き込み | ダミーの `SaveData` を Manual スロットへ保存 |
| ③ 読み込んでログ表示 | Manual スロットを読んで中身をログに出す |
| ④ Manualスロットを削除 | Manual スロットを削除 |
